# codex-ws

Codex CLIを `bin/codex-ws` 経由で使用し、コードレビュー・分析を実行するスキル。

## 実行コマンド

bin/codex-ws exec --full-auto --sandbox read-only "<request>"

## プロンプトのルール

**重要**: codex-ws に渡すリクエストには、以下の指示を必ず含めること：

> 「確認や質問は不要です。具体的な提案・修正案・コード例まで自主的に出力してください。」

## パラメータ

| パラメータ | 説明 |
| --- | --- |
| `--full-auto` | 完全自動モードで実行 |
| `--sandbox read-only` | 読み取り専用サンドボックス（安全な分析用） |
| `"<request>"` | 依頼内容（日本語可） |

## 使用例

**注意**: 各例では末尾に「確認不要、具体的な提案まで出力」の指示を含めている。**ai-workspace ルートをカレント**にしてから実行する（`bin/codex-ws` を相対パスで使うため）。

### コードレビュー

ai-workspace 内の複数リポジトリにまたがる作業ツリー／コミット差分をレビューする例。

bin/codex-ws exec --full-auto --sandbox read-only "ai-workspace 内の複数リポジトリ（projects/ 配下）にまたがる作業ツリー／コミット差分をレビューし、リスク・改善点を指摘してください。確認や質問は不要です。具体的な修正案とコード例まで自主的に出力してください。"

### バグ調査

複数プロジェクトにまたがる変更のうち、不整合や取りこぼしがないか調査する例。

bin/codex-ws exec --full-auto --sandbox read-only "複数プロジェクトにまたがる変更のうち、認証まわりの不整合や取りこぼしがないか調査してください。確認や質問は不要です。原因の特定と具体的な修正案まで自主的に出力してください。"

### アーキテクチャ分析

projects/ 配下のリポジトリを横断し、ワークスペース全体のつながりを整理する例。

bin/codex-ws exec --full-auto --sandbox read-only "projects/ 配下の関連リポジトリを横断して、このワークスペースのアーキテクチャ上のつながりを整理してください。確認や質問は不要です。改善提案まで自主的に出力してください。"

### リファクタリング提案

複数リポジトリにまたがる技術的負債をまとめて扱う例。

bin/codex-ws exec --full-auto --sandbox read-only "複数リポジトリにまたがる技術的負債を特定し、リファクタリングの優先順位と計画を提案してください。確認や質問は不要です。具体的なコード例まで自主的に出力してください。"

### デザイン相談（UI/UX）

bin/codex-ws exec --full-auto --sandbox read-only "あなたは世界トップクラスのUIデザイナーです。以下の観点からこのプロジェクトのUIを評価してください: (1) 視覚的階層構造とタイポグラフィ、(2) 余白・スペーシングのリズム、(3) カラーパレットのコントラストとアクセシビリティ、(4) インタラクションパターンの一貫性、(5) ユーザーの認知負荷の軽減。確認や質問は不要です。具体的な改善案をコード例付きで提示してください。"

bin/codex-ws exec --full-auto --sandbox read-only "UXリサーチャー兼デザイナーとして、このフォームのユーザビリティを分析してください。Nielsen の10ヒューリスティクスに基づき、(1) エラー防止の仕組み、(2) ユーザーの制御と自由度、(3) 一貫性と標準、(4) 認識vs記憶の負荷、(5) 柔軟性と効率性を評価してください。確認や質問は不要です。改善したTailwind CSSコードまで自主的に提示してください。"

## 実行手順

1. ユーザーから依頼内容を受け取る
2. **ai-workspace ルートをカレントにする**（`bin/codex-ws` が `bin/` から相対で解決できるようにする）
3. **プロンプトを作成する際、末尾に「確認や質問は不要です。具体的な提案まで自主的に出力してください。」を必ず追加する**
4. 上記コマンド形式で codex-ws を実行
5. 結果をユーザーに報告
